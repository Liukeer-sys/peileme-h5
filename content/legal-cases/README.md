路径为：`COMPANY_DISMISS_REASON` → 公司说是我的错 → `FAULT_DISMISS_CHECK` → 六种具体原因 → `FAULT_TRUTH_CHECK`。

六种原因最终共用“基本属实”“有这回事，但不确定严重程度”“公司在乱扣帽子”三个结果标识。因此，新MD使用 **分支标识＋具体选项** 保存关系，不能仅凭最后的结果标识混合取案：

```markdown
### FAULT_DISMISS_CHECK｜试用期没通过

- 关联程度：直接参考
- 争议侧重：事实与材料

面向用户的具体关联说明。
```

这里的关联程度仍表示案情相关性，不表示胜诉概率。用户选择“基本属实”也不等于法律上已达到解除程度。产品先读取具体原因筛选候选，再按直接参考优先、争议侧重匹配优先、同城优先排序。最后一题“基本属实”对应事实与材料，“有这回事，但不确定严重程度”对应严重程度，“公司在乱扣帽子”对应证据争议。侧重只改变排序，不删去不同结果的案例。

`争议侧重`是过错关系的必填维护字段，可用顿号分隔多个值，限定为`事实与材料`、`严重程度`、`证据争议`；不显示给用户。具体原因缺失或旧存档包含多个原因时不猜测精确匹配。

选择“其他问题或没说清楚”（`fault_reason_other_or_unclear`）时，汇总六种过错原因关联的全部去重案例，目前33案，同城优先。标题为“过错解除参考案例”，作为浏览参考，不标为情况接近；忽略历史残留的具体原因及属实程度答案。一个案件关联多个原因也只展示一次，小提示保留各原因的说明。沿用最多5张的循环叠放卡组，下载包含全部33案；不混入主动离职、被迫离职或协商离职的独有案例。

## 每份案例的固定结构

### 哪些内容展示给用户

2026年9月14日已逐一校订原40份文档的展示正文；2026年9月19日新增28份过错解除文档沿用相同规范。

- 展示：标题、背景、经过、已公开的双方主张、处理类型、结果，以及对应选项下的关系说明。正文直接讲事情、结果和与读者的关联，不夹入“本条应展示”“不能补写”“需要核对用户”等编辑指令。
- 来源入口：可显示原文名称、发布者、日期和链接。个人经历保留“当事人自述”，转载或第三方存档保留来源性质。
- 仅供维护：内部编号、历史标识、选项标识、争议侧重、核对日期及“信息边界”。搜索访问情况、未公开的细节和防止误写的提醒集中放在信息边界，不作为案情、结果或匹配说明输出。
- 没有公开的劳动者或公司主张：MD保留对应小节，正文只写“未披露”；读取后该项为空字符串，页面省略该栏目及标题。不得根据行为反推未公开的诉讼请求，也不以重复背景填满栏目。

会影响理解的事实区别仍在正文保留，例如个人自述与裁判认定、请求金额与实际获支持金额、和解总额与单项补偿、约定付款与实际到账。

1. 标题：供产品直接展示的中文标题。
2. 案情简介：包含背景、经过、劳动者主张、公司主张四个小节。没有公开的主张只写“未披露”，读取时转为空字符串，不反向猜测。
3. 结果：法律案例保留“判决结果”；协商离职经历使用“协商结果”，一份文档只能有其中一个章节。“处理类型”明确区分司法处理与个人经历。正文区分请求金额、获支持金额、协议金额和实际到账金额，不将自述收款写成法院认定。
4. 来源信息：内部标识、历史标识、城市、发布机构、发布日期、案号或定位、原文、补充来源、核对日期、信息边界。
5. 和用户离职方式的关系：最终选项使用程序现有的固定标识；过错解除使用`FAULT_DISMISS_CHECK｜具体选项文字`作为小节标题，并必填`争议侧重`。填写关联程度和面向用户的关系说明；一个案件可包含多个关系小节。

修改正文不影响读取；请保留约定标题、字段名及选项标识。来源采用完整 Markdown 网页链接。资料未公开的案号、金额、答辩、生效情况需要保留说明，不能为了填满格式而推断。

## 程序如何读取

入口：[legalCaseDocuments.ts](../../src/data/legalCaseDocuments.ts)。

`legalCaseDocuments` 自动读取本目录所有案例文件，README不参与。每条数据包括 `title`、`facts`、`result`、`source`、`relations`；这些字段全部来自同一份 Markdown，不依赖旧案例库、旧阅读覆盖表或旧匹配说明。

`result.heading` 保留MD的“判决结果”或“协商结果”标题，`result.type` 保留处理或经历类型。页面按实际类型显示，结果区域分别使用“处理结果”或“协商结果”，不会把协商经历写为裁判。

`source.limitations` 为维护备注。`facts.workerClaim`、`facts.companyClaim` 可能为空，展示时应省略对应栏目。

`getCaseDocumentsForReason(reasonId, optionLabel?)` 可返回候选案例及关系说明，直接参考排在同类参考之前。原有最终选项只需传`reasonId`，过错解除需同时传分支标识与具体选项文字。“其他情况”的待细化条目不会自动返回。这个函数只提供候选，不替代后续的完整用户条件排序，也不参与赔偿金额计算。

展示入口：[legalCasePresentation.ts](../../src/data/legalCasePresentation.ts)；卡片组件：[LegalCaseGallery.tsx](../../src/components/LegalCaseGallery.tsx)。`self_resign_normal`、`self_resign_reason`下的8个具体选项、`company_proposed_mutual_termination`、`FAULT_DISMISS_CHECK`下的六种具体原因及其其他情况、`NO_FAULT_DISMISS_CHECK`下身体原因、不能胜任、客观情况变化的九个最终选项和`nofault_not_listed_excuse`，以及经济性裁员的三个`layoff_*`最终选项，均使用新文档。其他离职方向继续使用原有匹配。

匹配关系以每份MD中的`relations`为准，README仅是阅读索引。明确选项按具体关系筛选，直接参考排在同类参考前，同一关联程度内优先同城；不截断为5条。“其他情况”由展示入口汇总SELF_RESIGN_REASON下全部去重案例，均作为浏览参考，同城优先。底层精确候选查询仍排除待细化关系，汇总浏览不改变赔偿计算。

案情的四个小节合成连贯段落，不显示“背景”“经过”“劳动者主张”“公司主张”等小标题；未公开的主张自动省略。所有案例画廊使用循环叠放卡组：最多露出5张，上方最多4张收起，只露城市和类型栏；最下面始终1张展开，初始为匹配排序第一的案例。点击后排卡片后选中项移到最前展开，其下方卡片转到循环队列后方；超过5张的内容随切换补入，无分组。上一例、下一例按完整候选顺序循环，显示原始序号和总数；换位、展开与补卡有动画，尊重系统减少动态效果设置。下载仍包含全部候选，不受5张可见上限影响。展开后保留标题、来源入口、处理结果和小提示。内部编号和信息边界不输出到卡片及下载包。
