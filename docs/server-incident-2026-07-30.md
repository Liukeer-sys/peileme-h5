## 发现的风险

- 主机 UFW 和 fail2ban 未启用。
- root 密码登录处于开放状态，公网存在持续扫描和 SSH 爆破风险。
- 公网 `5000` 端口上的既有 Python `ThreadingHTTPServer` 在取证时有约 53 条已建立长连接，并持续记录 `ConnectionReset`；这是当时最明显的单服务连接压力点。

该 5000 端口属于现有业务，取证期间保持只读，没有停止或改动。

## 本次部署采用的隔离措施

- 赔了么仅绑定 `127.0.0.1:18083`，不直接暴露应用端口。
- 数据库和 API 只使用 Docker 内部网络。
- Web/API/数据库设置内存、CPU 和日志上限。
- 三个容器均使用 `unless-stopped` 守护和健康检查。
- HTTPS、上传大小、文件签名和私有文件访问均在独立链路内控制。

## 后续建议

1. 先确认公网 5000 服务的真实用途和调用方，再为其增加反向代理、连接超时、并发上限和访问控制。
2. 配置 SSH 公钥与备用登录路径后，关闭 root 密码登录。
3. 启用 fail2ban，并根据现有业务端口清单设计 UFW/云安全组白名单。
4. 为主机配置少量 swap 或 zram，作为突发内存压力的缓冲。
5. 接入主机级连接数、OOM、磁盘延迟和容器重启告警。
