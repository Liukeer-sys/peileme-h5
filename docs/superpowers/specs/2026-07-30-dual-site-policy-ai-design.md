# 赔了么双站产品与生产架构设计

- 日期：2026-07-30
- 状态：已完成逐段确认，待书面复核
- 目标域名：
  - `https://peileme.art`：纯规则政策测算版
  - `https://ai.peileme.art`：完整 AI 分析版

## 1. 背景与目标

现有产品已经具备移动端测算、账号、历史、邀请码、材料上传、基础管理后台和生产部署，但政策计算仍依赖前端近似逻辑，文件分析内容缺少真实处理链，付费、规则管理、模型路由、运营后台和完整监控尚未形成生产闭环。

本次改造将产品拆为两个独立前端，共享账号、数据、交易和模块化后端：

1. 主站提供清晰、稳定、可解释的政策计算，构建产物不包含 AI 功能。
2. AI 站提供离职补偿专项分析与劳动文件签署前审查。
3. 两个站均采用按次收费，价格和免费权益由后台配置。
4. 政策规则和地域参数由后台管理，所有结果可追溯到具体规则版本。
5. 模型层参考 OranMemory 的 Provider 配置方式和 nms-flow 的生产级降级机制。
6. 保持现有移动 H5 的主要视觉语言和交互习惯，优先提升效果、完成率和失败恢复体验。

## 2. 已确认的产品决策

### 2.1 双站边界

#### 主站 `peileme.art`

- 政策测算
- 补偿金额计算
- 逐步计算过程
- 法规依据
- 证据清单
- 账号、历史、邀请码、订单与支付
- 首次完整测算免费，之后默认 `¥9.9/次`
- 全部计算由服务端规则引擎执行
- 前端源码、构建产物和运行请求均不包含 AI 能力

#### AI 站 `ai.peileme.art`

- 基础政策测算
- 离职补偿完整分析
- PDF、Word、图片材料识别
- 证据缺口和补强建议
- 法规及真实案例检索
- 风险结论与行动建议
- 可下载分析报告
- 劳动合同、Offer、离职协议等签署前审查
- 免费风险预览
- 完整离职分析默认 `¥39.9/次`
- 文件审查默认 `¥29.9/份`

### 2.2 账号与数据

- 两个站共享账号、登录态、用户资料、邀请码、订单和历史记录。
- 所有业务记录带有 `product_channel`，取值至少包括 `main`、`ai`、`admin`。
- 所有测算记录保存规则版本和地域参数快照。
- 所有 AI 结果保存 Prompt、Schema、路由和知识库版本。
- 已购买结果可永久回看；AI 专属内容只在 AI 站展示。

### 2.3 收费与权益

- 采用按次收费，不设计订阅和储值钱包。
- 主站首次完整测算免费，后续新测算按次收费。
- AI 站免费展示风险预览，完整结果按次收费。
- 同一付费 AI 任务包含：
  - 一次完整分析；
  - 24 小时内一次材料补充和重新分析；
  - 围绕本次报告的三次追问；
  - 最终结果永久回看。
- 商品价格、上下架、活动价、免费次数、补充次数和追问次数均由后台配置。

### 2.4 地域覆盖

- 全国省、市行政区划均可选择。
- 优先补齐全国省级规则和地级市参数。
- 地级市参数优先引用当地政府、人社局或统计局公开来源。
- 可信数据缺失时允许用户手工输入，并将结果标记为估算。
- 后台持续展示地域数据覆盖率、过期项和待审核项。

## 3. 总体架构

```text
Internet
  |
  +-- peileme.art ----> web-main --+
  |                                |
  +-- ai.peileme.art -> web-ai ----+--> shared-api --> PostgreSQL
                                           |         -> Redis
                                           |         -> S3/MinIO
                                           |
                                           +--> ai-worker
                                           +--> document-worker
                                           +--> scheduled-jobs

Observability:
OpenTelemetry -> Prometheus/Grafana
             -> Loki
             -> Alertmanager -> Feishu
```

### 3.1 服务边界

- `web-main`：纯规则版独立前端。
- `web-ai`：AI 版独立前端。
- `shared-api`：认证、用户、规则、测算、商品、订单、支付、历史、运营和管理 API。
- `ai-worker`：事实抽取、检索、分析、报告和追问。
- `document-worker`：文件校验、病毒扫描、OCR、解析和脱敏。
- `scheduled-jobs`：订单查单、退款查询、对账、数据过期提醒、备份检查和清理任务。

初期允许 `shared-api`、`ai-worker`、`document-worker` 共享一个代码仓库和镜像，通过不同进程入口独立扩缩容。

### 3.2 登录互通

- Refresh Token 使用 `Secure`、`HttpOnly` Cookie。
- Cookie Domain 设置为 `.peileme.art`，Path 限定在认证接口范围。
- Access Token 使用短有效期，并支持 Refresh Token 轮换和会话撤销。
- 两个域名均执行 CSRF Token 校验和严格 Origin 白名单。
- 用户可查看并退出其他设备；管理员可强制撤销会话。

## 4. 政策规则引擎

### 4.1 输入

- 用人单位所在地
- 合同类型
- 入职、解除或终止日期
- 解除主体、解除原因
- 通知方式和提前通知情况
- 解除前十二个月应发工资明细
- 奖金、津贴和补贴
- 已支付补偿
- 工龄承继
- 医疗期、孕期、产期、哺乳期等特殊状态
- 当地统计参数或用户手填参数

### 4.2 输出

- `N`、`N+1`、`2N`、可能无补偿等候选结论
- 适用前提和完整判断路径
- 工龄折算、工资基数、三倍封顶和十二年上限
- 已支付金额、理论金额和差额
- 信息缺失时的金额区间
- 影响结果的缺失项和争议项
- 法规条款、地域参数、数据来源和适用日期
- 规则版本与计算快照

### 4.3 规则配置模型

规则采用受控决策表和声明式表达式：

- `rule_set`：规则集合、适用产品和当前状态
- `rule_version`：版本、发布说明、生效区间和审核信息
- `rule_condition`：字段、操作符、值、分组和优先级
- `rule_action`：结论类型、公式模板、提示和证据要求
- `regional_parameter`：地区、年度、参数类型、数值和单位
- `legal_source`：法规名称、条款、来源地址和有效状态
- `regression_case`：固定输入、期望路径、期望区间和边界说明

后台不接受 JavaScript、SQL 或其他可执行脚本。表达式解析器只开放金额、日期、工龄和条件组合所需的白名单函数。

### 4.4 发布流程

```text
草稿
→ 格式校验
→ 全量回归
→ 人工审核
→ 定时或立即发布
→ 运行监控
→ 必要时回滚
```

每次发布产生不可变版本。历史测算继续引用原版本，重新测算使用当前有效版本。

### 4.5 精度等级

- `verified`：地域和年度参数有可信官方来源。
- `estimated`：使用上级地区参数或用户手填参数。
- `stale`：参数超过预期更新周期。
- `unsupported`：关键参数不足，系统只输出规则说明和待补项。

用户结果页显示精度等级和影响因素。

## 5. AI 与文档处理

### 5.1 任务类型

- `risk_preview`
- `document_extract`
- `legal_fact_extract`
- `severance_analysis`
- `document_review`
- `case_retrieval`
- `report_generation`
- `report_followup`

每种任务拥有独立 Prompt、输出 Schema、Provider 链、预算和超时。

### 5.2 处理流水线

```text
文件上传
→ MIME、大小、页数和压缩率校验
→ 病毒扫描
→ OCR 或文本提取
→ 敏感字段识别与最小化
→ 结构化事实抽取
→ 用户事实确认
→ 规则引擎复算
→ 法规及案例检索
→ AI 综合分析
→ Schema 和引用校验
→ 报告生成
```

### 5.3 结果要求

- 分离已确认事实、待确认事实和矛盾信息。
- 金额结论引用规则引擎结果。
- 每项证据说明证明目的、当前状态和补强建议。
- 真实案例必须包含案号、法院、裁判日期、裁判要旨和来源。
- 检索不到可靠案例时返回明确的空结果。
- 文件审查输出问题条款、风险解释、修改建议和建议文本。
- 页面和报告明确标识 AI 生成内容。

### 5.4 Provider 配置与降级

Provider 配置结构参考 OranMemory，首发复用现有 Tuzi 和 DataEyes 的服务端密钥。可靠性行为参考 nms-flow：

- 按任务配置有序 Provider/模型链。
- 短暂网络错误、408、429 和 5xx 执行带抖动的指数退避。
- 连续失败触发进程级熔断，冷却后半开探测。
- 支持手动停用 Provider。
- 首字超时触发备用链。
- 流式输出只在首个正文 Token 产生前切换 Provider。
- 产生正文后的流式失败进入可恢复失败状态，避免拼接答案。
- JSON Schema 失败进入结构修复或备用模型。
- 可选延迟对冲默认关闭，由后台按任务启用。
- 所有调用记录用途、Provider、模型、阶段、结果、耗时、尝试次数、降级状态和费用估算。
- 调用遥测不保存 Prompt、文件正文和完整回答。

后台允许修改 Provider 启停、模型、优先级、超时、重试、熔断、Prompt 版本和预算。API Key 只保存在生产密钥配置中，后台显示掩码和连接测试状态。

### 5.5 文件安全和生命周期

- 文件使用随机对象键并绑定用户和任务权限。
- 支持 PDF、DOCX 和常见图片格式。
- 加密文件、损坏文件、危险文件和超限文件返回明确状态。
- 文档中的指令统一作为不可信内容处理，隔离提示注入。
- 原文件、提取文本和报告可设置不同保留期限。
- 用户可删除单个文件、单个任务或整个账号数据。

## 9. 可观测性、备份和运行安全

### 9.1 指标与日志

- OpenTelemetry 统一请求与任务链路 ID。
- Prometheus 采集应用、数据库、Redis、队列、容器和主机指标。
- Grafana 展示系统和业务仪表盘。
- Loki 集中检索结构化日志。
- Alertmanager 发送飞书告警。

重点告警：

- API 错误率和 P95 延迟
- 支付回调失败和对账差异
- AI 降级率、全链失败率和成本突增
- 队列积压和任务超时
- PostgreSQL 连接、锁和磁盘
- Redis 内存和持久化
- 容器重启和主机 OOM
- 证书过期
- 备份失败和恢复演练过期

### 9.2 备份

- PostgreSQL 每日全量备份。
- 持续归档 WAL，支持时间点恢复。
- 文件对象和数据库备份加密复制到阿里云 OSS。
- 保留本地短周期副本和异地长期副本。
- 每月在隔离环境执行真实恢复演练并保存结果。

### 9.3 资源隔离

- API、AI Worker、文档 Worker 独立进程和容器。
- 每个容器设置 CPU、内存、并发和任务超时限制。
- OCR 和模型任务进入队列，限制单用户和全局并发。
- 健康检查、自动重启和服务器重启自恢复纳入发布验收。

## 11. UX 设计

### 11.1 主站

```text
首页
→ 地区和劳动信息
→ 表单校验
→ 首次免费或支付
→ 计算结果
→ 法规依据和证据清单
→ 保存、分享和历史回看
```

保留现有 H5 颜色、卡片、字号层级和主要动效。删除 AI 文案、AI 入口和文件审查入口。结果页强化计算过程、数据来源、精度等级和修改重算。

### 11.2 AI 站

```text
选择分析类型
→ 背景问卷和材料上传
→ 解析进度
→ 用户确认事实
→ 免费风险预览
→ 支付
→ 完整报告
→ 补充材料或追问
→ 下载和历史回看
```

关键 UX：

- 文件上传后持续显示真实任务阶段。
- OCR 或模型失败允许恢复和重试。
- 用户在付费前确认已提取事实，减少错误分析。
- 报告使用移动端锚点导航，区分金额、证据、风险、案例和行动。
- Provider 切换对用户透明，长等待时展示明确进度。
- 支付取消或超时保留已填写内容。

6. 在未切流地址执行 API、浏览器和任务验收。
7. 主站使用蓝绿切换。
8. 新增 AI 子域名解析和证书。
9. 验证外网访问、自动重启和持久化。

## 13. 测试与验收

### 13.1 自动化层级

- 规则引擎单元测试和参数化法规案例
- 金额、日期和工龄边界属性测试
- Provider 路由、重试、熔断、超时和流式失败测试
- 文件解析、权限、生命周期和提示注入测试
- 订单状态机、支付回调、幂等、退款和对账测试
- API 集成测试，使用真实 PostgreSQL、Redis 和对象存储
- Playwright 移动端和桌面端完整用户链路

### 13.2 Playwright Happy Path

- 邮箱注册、登录和跨域会话
- 主站首次免费测算
- 主站后续付费测算
- AI 风险预览、支付、真实模型分析、补充材料和追问
- 文件审查和报告下载
- 历史回看
- 邀请码归因
- 管理后台规则发布、价格修改、公告发布、订单查询和任务回查

### 13.3 Playwright Unhappy Path

- 错误、过期和频率受限验证码
- 重复注册、错误密码和会话过期
- 非法金额、边界工龄、地域参数缺失或过期
- 文件超大、损坏、加密、危险和无文本
- Provider 首字超时、降级、全链失败和恢复
- 支付取消、超时、重复回调、金额不符和退款失败
- 重复点击、刷新、弱网和断线恢复
- 普通用户访问他人记录或管理接口
- 后台角色权限与前端按钮一致性

### 13.4 真实验收证据

- 数据库持久化记录
- 订单和渠道流水
- Provider 路由和降级日志
- 文件对象和权限验证
- 后台截图
- Grafana 指标和告警
- Playwright HTML 报告、截图和录像
- 外网真实域名访问
- 容器重启与服务器重启恢复
- 备份恢复记录

支付先完成官方沙箱全链路；商户生产配置就绪后，执行一笔小额真实支付和退款验收。外部收银台身份确认由用户配合完成，Playwright 验证收银台前后全部应用链路。

## 14. 上线门槛

- 两个前端独立构建，主站产物中无 AI 功能。
- 规则回归测试全部通过。
- 重点地区参数有来源和有效期。
- 价格、免费权益和规则均可由后台配置。
- 账号、订单、支付、退款和权益闭环通过。
- AI 真实调用、降级和失败恢复通过。
- 管理后台覆盖用户、规则、公告、交易、AI、日志和监控。
- PostgreSQL、Redis、文件和队列数据均持久化。
- 生产服务受进程守护，重启后自动恢复。
- 外网真实域名、HTTPS 和 API 健康检查通过。
- Playwright Happy/Unhappy Path 全量报告通过。
- 生产支付和 Provider 凭据仅存在于服务器密钥配置。
